# ADR 0038：從 App 直接開啟會員中心、審核通知派送

日期：2026-11-24。來源：行動大學的請求（杜杜龍要求）。

## 決定
1. `GET /auth/sso/adopt` 的 `return` 若是中央自己的 `/my/edit` 或 `/my/<會員編號>`，adopt 除了記住瀏覽器的共用登入，還會替該會員建立中央網站自己的 session（一般的 12 小時登入），再導向該頁，不再經過 Google 帳號選擇。code 沿用單次、2 分鐘；失效時導向 `/login?return_to=…`。其他中央路徑與其他網站一律 400。不新增專用端點。
2. 審核規則改版（杜杜龍 2026-11-24 確認「要改」，串接指令 `2026-11-24.2`）：獎銜只要不是「無」一律審核；中心在系統是寰宇時審核（實際中心或明確勾「無」），系統不是寰宇時中心自動「無」不審核；系統本身不審核。
3. 派送：寰宇＋實際中心 → 該中心審核員（沒有時秘書與超管）；其他（中心無或沒填、系統非寰宇含無／其他）→ 只給 secretary 與 super_admin，中心審核員看不到。會員改中心或系統時，等待中的獎銜申請會改派到對應審核者（舊申請作廢、新申請重發）；離開寰宇後獎銜仍待審，改由總部審核。
4. 不處理：既有已存的獎銜不會被大量補審（修復工作只補寰宇＋中心者）；會員下次改動系統或中心時才會連動補審。
5. 串接指令升 `2026-11-24.1`、`2026-11-24.2`，檢查清單新增 37、38。

## 影響
中央網站的 session 與 App 的共用登入分開存放；App 登出共用登入不會自動登出已開啟的會員中心頁（與先前行為相同）。

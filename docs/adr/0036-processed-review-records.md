# ADR 0036：審核「已處理紀錄」可保存姓名與申請內容快照

日期：2026-11-22　狀態：採用（杜杜龍決定，行動大學需求）

## 背景
串接指令三、16 原本規定 App「不保存申請內容與名單」，三、7 禁止 App 保存 Amway 資料（含獎銜）。審核人員處理完後，App 要留一份「已處理紀錄」（誰申請、誰審核、結果、時間）供日後查詢；沒有申請人姓名只能顯示「會員」，沒有申請內容看不出處理了什麼。精神與三、11「交易紀錄存當時快照」相同。

## 決定（只改規範文字，不改程式、不新增 API）
- 允許 App 在**審核完成後**的已處理紀錄保存：申請人姓名快照（處理當下的 `display_name`，不跟著改名）；申請內容快照（欄位名稱、原本的值、申請的值、修改後通過的值，獎銜存代碼或中文名稱皆可）；處理結果、處理時間、審核人員顯示名稱。待審中的申請不保存。
- 三、7 加註唯一例外：僅限這份已處理紀錄、只存申請當下的快照、不得用來判斷資格或權限（資格一律即時向中央查詢）。
- 仍禁止：Amway 會員編號、上手、資格查詢結果、整份待審名單、搜尋字；姓名與申請內容不進日誌、分析工具、錯誤回報。
- 收到 `member.deleted`：清空該會員在已處理紀錄裡的姓名與申請內容快照，不用刪整筆。
- 檢查清單 28 改寫；29 的「member_id、field_key 不保存」改為「待審中的不保存，已處理紀錄依三、16」（否則與新規則矛盾）；新增 33「規則放寬、沒有新的程式要做」，原 33 改 34。串接指令升 `2026-11-22.4`。

## 後果
中央沒有程式變更；已串接且不需要這份紀錄的 App 不必改。

# ADR 0004：會員編號、重複偵測、夫妻綁定

狀態：已採用（2026-11-10，PR 4）

## 決定
- 「會員編號」與「Amway會員編號」是同一個欄位 `member_number`（有順序的 `{country, number}` 清單），只有顯示名稱不同；由 `PUT /v1/me/profile/fields/member_number` 整份寫入，scope `profile.basic.write`。
- 未勾選「我是Amway會員」最多 1 組，勾選後最多 50 組（勾選開關的 API 在 PR 5）。第一組是預設編號：公開網址 `https://id.hglobal1985.com/<編號>` 與客服識別碼。編號一律公開，不能改成隱藏。
- **編號允許重複**：資料庫不加唯一限制。只有系統隨機產生的編號會避開所有已存在的編號。
- 隨機規則：`<國家代碼><0 開頭的 7 位數>`（例如 `TW0112342`），以密碼學亂數拒絕抽樣；同長度連續 8 次撞號就加長到 8、9、10 位。國家用註冊時的 IP 國家，查不到用 `TW`。每位新會員註冊時就會拿到一組。
- 會員自改 24 小時最多 3 次（超過回 429 `rate_limited` 與 `Retry-After`）；重送相同清單不算次數。系統產生的編號不算次數。全部留稽核。
- 重複偵測：不論是否勾選 Amway，儲存時比對（國家＋編號），回傳 `duplicate_candidates`（姓名、頭像、獎銜；不遮罩）。對方會員識別碼不外流，改用 1 小時有效、只限本人使用的 `candidate_id`。
- 夫妻綁定：`POST/GET/DELETE /v1/me/spouse`，`profile.spouse.write`（GET 也接受 `profile.read`）。單方同意即時生效、最多一人（`spouse_members` 主鍵保證）、`spouse_already_bound`。被綁定方收到站內通知（`notifications` 表）。
- 綁定後共用編號清單：比對到的編號排第一，接著發起方、再被綁定方的其他編號，去除重複；之後任一方修改，兩人同步。上手資料不共用。
- 解除：任一方都可解除；獎銜不變；**發起綁定的一方**換成新的隨機編號（規則中兩種情況結果都是發起方），另一方保留清單。對方收到 `spouse.unbound` 通知。

## 後續

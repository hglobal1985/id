# ADR 0029：服務可以新增「職稱」詞條（待核可）

日期：2026-11-15。狀態：程式已寫並測試；部署後要實測。來源：行動大學（業主授權）。

## 決定
- 新增 `POST /v1/vocab/suggestions`，body `{ "pool": "job_title", "value": "區域經理" }`，用 **App 的服務 token**（與聯絡查詢、會員資料查詢同一種；不是會員登入）。沒帶或錯誤 401。
- **只開放 `job_title`**：其他詞庫（中心、獎銜、行業類別…）一律 403，避免誤用。不需要在後台為 App 另外開權限：能拿到服務 token＝業主已替這款 App 建立服務金鑰；風險由「待核可」「限制」「稽核」承擔。
- **驗證**：`value` NFKC 後去除前後空白，最長 50 字（以字元計），不可空白、不可含控制字元；不合 `400`（含格式錯誤的內容）。未帶 token 的請求一律先回 401。
- **重複**：以 `normTerm`（不分大小寫、全形半形）比對，已有就回既有的詞，`created: false`，不寫稽核。
- **待核可（建議，已採用）**：新詞存為 `pending = 1`（migration 0029，另記 `suggested_by` App），**不出現在會員的建議清單**，也不進下拉清單；後台「關聯詞」頁的分頁標籤顯示「待核可 N」，每個待核可的詞有「核可」按鈕（`POST /v1/admin/vocab/{pool}/approve`，超級管理員）；刪除＝拒絕；管理員把它合併進別的詞也視為核可。會員自己打同一個詞不會讓它跳過核可。
- **限制**：每個 App 每分鐘 30 次（沿用寫入限流，`429`）；全站待核可最多 200 個（`429`，`retry-after: 3600`）。
- **稽核**：每次實際新增記 `vocab.suggest`（actor＝App、時間、`{pool, term}`；職稱不是個資）；核可記 `vocab.approve`。
- 不讀寫任何會員自己的職稱資料。

## 行動大學的重送規則（對方已實作）
404／405／501＝未開放；401、429、逾時、5xx 暫存重送；400 是內容不合，不重送。

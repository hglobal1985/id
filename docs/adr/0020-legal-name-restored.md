# ADR 0020：恢復「真實姓名」欄位（legal_name）

狀態：程式已寫（PR 待合併）；**畫面與隱私文字待業主核准後才部署正式環境**。業主 2026-11-12 決定恢復（2026-11-11 曾於 ADR 0014 永久刪除 `primary_name`）。

## 用途
寰宇行動大學的付費課程報名審核與對帳（金流）需要辨識繳款人。除此以外不使用。

## 決定
- **欄位 key：`legal_name`**，標籤「真實姓名」，放在基本資料（順序在顯示名稱之後），最長 50 字，文字欄位，**預設隱藏**（會員可自行改為公開，但畫面說明只講對帳用途）。寫入範圍 `profile.basic.write`；欄位定義版本 `2026-11-12.1`。
- **不沿用 `primary_name`**：舊 key 維持 404，避免舊資料或舊快取被誤認為可恢復；`legal_name` 是全新欄位，所有人從空白開始。
- **歷史值無法恢復**：migration 0013 對 `profile_field_values`、`profile_visibility` 做了 `DELETE`，沒有備份表。D1 的時間點還原只能整個資料庫一起倒回，會連同之後的所有會員資料一起回退，不可行。會員需重新填寫。（若業主要補舊名單：只有舊來源資料庫 `echoes_db` 的 77 位匯入對象可能還有名字，需業主決定是否使用。）
- **行動大學的讀取方式（最小讀取）**：用登入會員本人的 Access Token 呼叫既有的 `GET /v1/me/profile`，讀 `fields.legal_name.value`。**不新增**任何管理端或 App 端讀取「別人」資料的接口。App 只在「報名付費課程」與「對帳」當下現讀；不保存到 App 資料庫、日誌或分析工具，對帳只留訂單與 `member_id` 的對應。
- 稽核紀錄只記欄位名稱，不含值（既有行為，已有測試）。刪帳號時隨基本資料一併移除。
- 串接指令 `2026-11-12.8` 新增一段說明。

## 待業主核准的文字（尚未寫進 `privacy-policy.ts`）
1. **畫面欄位說明（已在欄位定義，部署前請核准）**：「用於付費課程報名與對帳，預設不公開。」
2. **隱私權政策 §3「我們收集的資料」第 2 點**：現有文字已列「本名」，建議改為「真實姓名」。
3. **隱私權政策 §4「使用目的」新增一點**：「辨識付費課程報名的繳款人並進行對帳（您填寫的真實姓名；只有在您報名付費課程或對帳時，合作營運單位才會以您本人的登入讀取，不會公開，也不會用於其他用途）。」
4. **隱私權政策 §5「公開與分享」合作營運單位那一點補一句**：「真實姓名預設不公開，僅在您報名付費課程時提供給合作營運單位。」
5. 《隱私同意文字（第二版）》是 Amway 跨系統資料互通的專用文件，與本欄位無關，建議不修改；若業主希望在報名付費課程當下另外顯示一段同意文字，請另行指示。
